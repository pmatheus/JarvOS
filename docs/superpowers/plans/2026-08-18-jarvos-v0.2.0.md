# JarvOS v0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** An ISO whose install is short, silent and good-looking: prebuilt binaries, a
Bubble Tea cockpit instead of package spam, the desktop up in minutes, and everything
else offered by a native app at first boot.

**Spec:** `docs/superpowers/specs/2026-08-18-jarvos-two-stage-install.md`

## Global Constraints

- **Nothing compiles on the user's machine.** Stage 1 uses `pacman` only.
- Stage 1 target: **≤ 8 min** boot→SDDM in QEMU on this box; measured and reported.
- Binary repo `[jarvos]`: GitHub Release `repo-x86_64` on `pmatheus/jarvos-iso`,
  `SigLevel = Required DatabaseOptional`, signed with the dedicated "JarvOS Repo" key.
  Private key never leaves the box, never enters git; public key ships in the ISO.
- TUI: Go + Bubble Tea/Lipgloss, `CGO_ENABLED=0` static binary, console-safe
  (16 colours, box drawing, no emoji), keys `d` log / `s` root shell on tty3 / `q` when done.
- Raw installer output goes to `/var/log/jarvos-install.log` only.
- Bash: `set -euo pipefail`, 4-space indent, shellcheck -S warning clean.
  Go: `gofmt`, `go vet`, table tests. QML: `.qmlformat.ini`, 4-space, ≤110 cols.
- Local builds only — never hosted CI. Clean commit messages, no AI references.
- Two repos: `~/jarvos-iso` (ISO, TUI, repo tooling) and `~/JarvOS` (runtime, stage-1
  package set, Setup app, module catalogue). JarvOS main must stay pushed.

## Contract: `/run/jarvos-install/state.json` (written by `jarvos-install`, read by the TUI)

```json
{ "version": 1,
  "target": {"disk": "/dev/vda", "fs": "btrfs", "encrypted": false, "profile": "stage1"},
  "phases": [
    {"id":"disk",    "title":"Preparing the disk",        "state":"done",    "started_at":"…","ended_at":"…"},
    {"id":"base",    "title":"Installing the base system","state":"running", "step":37,"total":152,"message":"quickshell"},
    {"id":"desktop", "title":"Installing the JarvOS desktop","state":"pending"},
    {"id":"finish",  "title":"Finishing up",              "state":"pending"}
  ],
  "log": "/var/log/jarvos-install.log",
  "result": null }
```
`state` ∈ `pending|running|done|failed`. `result` is `null`, `"ok"`, or
`{"error":"…","phase":"…"}`. Writes are atomic (temp file + rename). The TUI polls every
250 ms and never fails on a partially written file (keeps the last good state).

### Task 1 — `[jarvos]` binary repo (owner of everything pacman-config related)

**Files (jarvos-iso):** `bin/jarvos-repo-build`, `bin/jarvos-repo-publish`,
`repo/packages.txt` (the AUR list), `configs/airootfs/etc/pacman.conf` (add `[jarvos]`),
`configs/airootfs/usr/share/jarvos-iso/jarvos.gpg`, `test/unit/repo-build-test.sh`.

- `jarvos-repo-build [--all|pkg…]`: builds each package in a clean chroot (`devtools`,
  e.g. `extra-x86_64-build`; install `devtools` if absent), signs the artifact, and runs
  `repo-add -s -v repo/x86_64/jarvos.db.tar.zst`. Skips a package whose exact version
  already exists unless `--force`. Never builds as root; never touches the host system.
- `jarvos-repo-publish`: `gh release create repo-x86_64 --title … --notes …` if missing,
  then `gh release upload repo-x86_64 repo/x86_64/* --clobber`. Prints the Server URL.
- Signing key: create "JarvOS Repo <pmatheus.nsx@gmail.com>" if absent (4096 RSA, no
  passphrase is NOT acceptable — use a passphrase stored by the chairman in the vault;
  if no passphrase can be provided non-interactively, document the exact `gpg` command
  the chairman must run and fail loudly rather than creating an unprotected key).
- `packages.txt` v1 (verify each name against the AUR before building):
  `quickshell-git caelestia-shell caelestia-cli app2unit libcava qt6gtk2
  qt6-avif-image-plugin adw-gtk-theme-git ttf-gabarito-git ttf-readex-pro
  ttf-google-fonts-typewolf ttf-material-symbols-variable-git matugen-bin
  kde-material-you-colors python-materialyoucolor python-pywal16 bibata-cursor-theme-bin
  grimblast-git wlogout swww hyprland-qtutils timeshift-autosnap`
- ISO `pacman.conf` gains `[jarvos]` with `SigLevel = Required DatabaseOptional` and
  `Server = https://github.com/pmatheus/jarvos-iso/releases/download/repo-x86_64`.
- **Verification:** build at least `ttf-gabarito-git` and `quickshell-git`; publish;
  then, in a throwaway container or the archiso live env, `pacman-key --add jarvos.gpg`,
  `--lsign-key`, `pacman -Sy` and `pacman -S --downloadonly quickshell-git` with
  signature checking on. Paste the output in the report.

### Task 2 — Stage 1: package set, chroot-setup v2, state events

**Files:** JarvOS `system/packages/stage1.txt`, `bootstrap.sh` (accept `--stage1`),
jarvos-iso `configs/airootfs/usr/share/jarvos-iso/chroot-setup.sh`,
`configs/airootfs/usr/local/bin/jarvos-install`, `test/unit/*`.

- `stage1.txt`: exactly what the desktop needs to look right — base, linux, linux-firmware,
  NetworkManager, sddm, hyprland stack, quickshell-git + caelestia-shell/cli, kitty, fish,
  fonts, matugen/colour tools, uv, grub/efibootmgr, plus what `install.sh` deploys. Derive
  it from today's `dependencies.txt` + `aur-core.txt` by removing everything that is not
  needed for first light; list what you removed in the report.
- `chroot-setup.sh --stage 1`: installs `stage1.txt` with **pacman** (repos + `[jarvos]`),
  deploys dotfiles, enables sddm/NetworkManager, writes `/etc/jarvos-release`, marks
  first-run pending (`/var/lib/jarvos/first-run-pending`). No yay, no makepkg, no git clone
  of the JarvOS repo unless the dotfiles need it (prefer shipping the dotfiles from the ISO
  payload; if a clone is still needed, keep `--depth 1 --recurse-submodules`).
- `jarvos-install`: emit the state.json contract above (atomic writes), parsing pacman's
  `(37/152) installing foo` for step/total. Keep the raw log behaviour and the markers.
- **Verification:** `--dry-run` unit tests for the new flags; a real timed stage-1 install
  is Task 5's job.

### Task 3 — Installer TUI (Go + Bubble Tea)

**Files (jarvos-iso):** `tui/go.mod`, `tui/main.go`, `tui/state.go`, `tui/view.go`,
`tui/logview.go`, `tui/*_test.go`, `bin/jarvos-iso-make` (build step),
`configs/profiledef.sh` (declare the binary).

- Reads the state.json contract; renders the cockpit layout from the spec; `d` opens the
  live log full-screen with scroll; `s` spawns a root shell on tty3 (`openvt -sw` or
  `chvt`; ground the command) without killing the install; `q` only after `result != null`.
- Failure: red banner + log path + stays on screen (never reboots).
- Table tests for the state parser (partial file, unknown phase, failed result) and a
  golden test for one rendered frame at 80x24.
- `jarvos-iso-make` builds it (`CGO_ENABLED=0 go build -trimpath -ldflags "-s -w"`) into
  `configs/airootfs/usr/local/bin/jarvos-installer-ui` before `mkarchiso`, and the built
  binary is git-ignored.
- `.automated_script.sh` runs the TUI as the foreground UI, with `jarvos-install` as its
  child (like the current dashboard hand-off).

### Task 4 — First-run "JarvOS Setup" (QML) + module catalogue

**Files (JarvOS):** `system/modules/{apps,ai,security,dev}.module`,
`config/.config/quickshell/jarvos/modules/setup/*.qml`, a service singleton for the
backend, `scripts/jarvos-module-install`, autostart wiring, `bin/jarvos-setup`.

- `.module` format: `name`, `description`, `icon` (Material Symbols), `packages` (one per
  line), optional `post` script. Catalogue v1:
  - **apps**: brave-bin, google-chrome, zen-browser-bin, spotify, ferdium-bin,
    visual-studio-code-bin, obsidian
  - **ai**: hypr-box (local), claude-code, opencode, openai-codex (or codex-bin),
    antigravity, ollama
  - **security**: the current `aur-security.txt` set + clones of `chsoares/ezpz` and
    `chsoares/ctf.fish`
  - **dev**: docker, docker-compose, libvirt/qemu-desktop, uv, nodejs/npm, rustup, LSPs
- The app opens on first login (marker `/var/lib/jarvos/first-run-pending` →
  `~/.local/state/jarvos/first-run-done`), shows one card per module with size estimate,
  installs in the background via `jarvos-module-install <module>` (pacman/yay), reports
  progress into the bar, and never blocks the desktop. Skipping is a first-class button;
  `jarvos-setup` reopens it later.
- **Verification:** run the app against the live shell on this box (`qs -c caelestia`),
  screenshot it, and install one small module for real (e.g. a single package) proving
  progress and completion.
